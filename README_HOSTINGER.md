# محراب — دليل التثبيت والتشغيل

## المتطلبات
- PHP 8.2 أو أحدث.
- MySQL 8 أو MariaDB حديثة.
- Apache مع `mod_rewrite` أو إعداد Rewrite مكافئ على Nginx/LiteSpeed.
- امتدادات PHP: `pdo_mysql` و`mbstring` و`fileinfo`.
- HTTPS إلزامي عمليًا على الموقع الفعلي.

## تثبيت جديد
1. أنشئ قاعدة بيانات MySQL ومستخدمًا لها.
2. ارفع محتويات مجلد المشروع إلى مجلد الموقع.
3. افتح `/install.php` من المتصفح. التثبيت يدعم كذلك التشغيل داخل مجلد فرعي مثل `/mihrab`.
4. أدخل بيانات قاعدة البيانات، `APP_URL` الفعلي، وحساب المدير.
5. بعد نجاح التثبيت افتح `/admin/login`.
6. احذف `install.php` من السيرفر أو امنع الوصول إليه من إعداد الخادم.
7. شغّل `php tools/preflight.php` من CLI قبل الإطلاق.

لا تحتاج إلى تشغيل ملفات migrations عند التثبيت الجديد؛ `schema.sql` يحتوي البنية الكاملة.

## إعدادات التشغيل والأسرار
الإعدادات ليست مرتبطة بالكود. يمكن استخدام متغيرات البيئة أو `private/config.php`. متغيرات البيئة تتقدم على الملف.

في Production يفضّل وضع ملف الإعداد خارج مجلد الويب عبر `MIHRAB_CONFIG_FILE` أو استخدام مدير متغيرات البيئة في الاستضافة. لا ترفع `private/config.php` أو كلمات المرور إلى Git.

راجع `DEPLOYMENT_STANDARD.md` للقائمة الكاملة لمتغيرات `APP_*`, `DB_*`, `STORAGE_*`, `MAIL_*` وإعدادات Proxy/HSTS.

## تحديث موقع محراب موجود
لا تستبدل قاعدة البيانات ولا تحذف `uploads/` أو التخزين الخاص أو إعداد التشغيل.
اتبع `UPGRADE.md` وخذ نسخة احتياطية قابلة للاستعادة قبل أي Migration.

## النسخ الاحتياطي والاستعادة
قبل التحديث:

```bash
php tools/backup.php
```

فحص الجاهزية:

```bash
php tools/preflight.php
```

الاستعادة متاحة من CLI فقط، وتنشئ نسخة أمان جديدة قبل الاستبدال:

```bash
php tools/restore.php --backup=اسم-النسخة --confirm=RESTORE
```

## الأمان
- كلمات المرور باستخدام `password_hash`.
- PDO Prepared Statements.
- CSRF Tokens بما فيها المثبّت.  
- Cookies من نوع HttpOnly وSameSite مع Session Strict Mode.
- تجديد Session عند الدخول ودوريًا للحساب الإداري.
- عدم الثقة بـ `X-Forwarded-Proto` إلا عند تفعيل `TRUST_PROXY` صراحةً.
- HSTS قابل للتفعيل فقط بعد ضمان HTTPS.
- تقييد محاولات تسجيل الدخول عبر قاعدة البيانات عند توفر الجدول.
- منع تنفيذ PHP داخل `uploads/`.
- مرفقات الشكاوى تحفظ في مساحة خاصة.
- تحقق من نوع الصور وحجمها.
- صلاحيات إدارية حسب الدور.
- منع وصول الويب إلى ملفات التشغيل والنسخ الاحتياطية على Apache، مع ضرورة إعداد قاعدة مكافئة على Nginx.

## ملاحظات قبل الإطلاق
- راجع نصوص الخصوصية والشروط قانونيًا بحسب الدول المستهدفة.
- اضبط SSL/HTTPS ثم فعّل HSTS إذا كانت البنية جاهزة.
- انقل النسخ الاحتياطية المهمة إلى مخزن خارج نفس السيرفر.
- راجع إعدادات SEO والتكاملات من لوحة التحكم.
- اختبر الموقع على الهاتف والكمبيوتر.

## بيانات المواقع العالمية (v7)

عند ترقية موقع قائم، خذ نسخة احتياطية ثم طبّق `migrations/008_global_location_selector.sql` مرة واحدة. يحافظ هذا التحديث على السجلات القديمة ويضيف حقول المصدر والأسماء متعددة اللغات فقط.

لتحميل الدول المرجعية شغّل:

```bash
php tools/import_countries.php
```

ولتحميل مناطق المستوى الأول والمدن الواسعة من GeoNames، نزّل `admin1CodesASCII.txt` و`cities500.zip` من صفحة GeoNames Export، فك ضغط `cities500.txt`، ثم شغّل:

```bash
php tools/import_geonames.php --regions=/path/admin1CodesASCII.txt --cities=/path/cities500.txt
```

الاستيراد قابل لإعادة التشغيل: يحتفظ النظام بمعرّف المصدر ولا ينشئ نسخة مكررة من السجل نفسه. مصادر المرجع: mledoze/countries (متوافق مع REST Countries للأسماء والرموز)، وGeoNames للمناطق والمدن. لا تُنشأ ترجمات عربية مصطنعة؛ عند غياب الاسم العربي يبقى الاسم الموثق من المصدر.
